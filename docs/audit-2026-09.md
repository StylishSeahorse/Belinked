# Audit and hardening pass: September 2026

The scope was a full audit of Belinked as a single-owner link-in-bio app: security, correctness, UX, and feature gaps against Linktree-style products. The multi-user SaaS surface was deliberately left out.

## Architecture (unchanged fundamentals)

- **Next.js 16 App Router**, React 19, TypeScript, Tailwind 3.
- **SQLite via Prisma 6**, with `prisma db push` on container start. All schema changes in this pass are additive (new nullable or defaulted columns plus indexes), so `db push` applies them without data loss.
- **Server Actions** handle admin mutations, and **Route Handlers** serve public endpoints (`/api/track`, `/api/click/:id`, `/s/:code`, `/uploads/*`) and owner downloads (`/api/export`, `/api/qr`, `/api/link-preview`).
- **One `Owner` row** with DB-backed sessions (SHA-256 token hashes, HTTP-only cookie, 14 days). There are no users, tenants or roles.

## Key decisions

| Decision | Why |
| --- | --- |
| The public page is a **server component**. Data passes through `lib/public-data.ts` DTOs. | Previously every block, including hidden, archived and scheduled ones with their internal notes and destination URLs, was serialized to anonymous visitors. Now only visible, public fields leave the server, and the page ships almost no JS (just the `ViewBeacon` island). |
| Every admin mutation goes through `runFormAction`, which redirects back with a `?notice`/`?error` flash. `FormRestore` re-fills the form after an error. | Validation errors used to crash to Next's generic error page and lose the owner's edits. Unknown errors are logged server-side and shown only as a generic message. |
| Block positions are always rewritten as a dense `1..n` sequence (`lib/ordering.ts`). | Manual "position" inputs allowed duplicates and gaps. |
| Outbound fetches use `lib/safe-fetch.ts`. | The IP is validated at connect time via a custom DNS lookup, redirects are re-checked on every hop, and time and size are bounded. This closes redirect-based and DNS-rebinding SSRF. |
| Analytics store a **daily-rotating HMAC visitor hash** and never the IP. Country comes only from CDN headers. | This gives unique-visitor counts without persistent identifiers or a GeoIP database. |
| Login throttling uses a per-IP limit **and** a global failure cap. `X-Forwarded-For` is only trusted with `TRUST_PROXY=true`. | A spoofed XFF header previously gave unlimited password guesses. |
| Password recovery uses the CLI (`npm run owner:reset-password`), not email. | This fits a self-hosted single-owner app, and it works without SMTP. |
| Theme values are normalized and sanitized in one place (`normalizeTheme`). | These values are written into inline CSS. |
| Embeds come from an allow-list only (`resolveEmbed`), are rendered in sandboxed iframes, and are also restricted by CSP `frame-src`. | This prevents arbitrary iframes and HTML injection. |

## Intentionally not built

- **Multi-user features:** registration, teams, roles, billing and subscriptions are out of scope for a single-owner app.
- **Custom domain management:** point DNS or a reverse proxy at the app and set `APP_URL`. Canonical, OG, sitemap and QR URLs all derive from it.
- **PWA and offline admin:** these add little for a page that visitors open from a bio link.
- **Payments and digital downloads:** product blocks link out to an external shop instead.
- **Raw HTML, JavaScript or custom CSS blocks:** these would create a stored-XSS and remote-code surface. Only allow-listed embeds are supported.
- **IP geolocation:** it would need a GeoIP database and privacy disclosures. Country data is available when a CDN supplies it.

## Known limitations

- The CSP allows `'unsafe-inline'` scripts because Next.js injects inline bootstrap scripts. A nonce-based CSP would need the proxy/middleware pipeline and dynamic nonces. The remaining CSP still blocks framing, plugins, `<base>` hijacking, cross-origin form posts, and non-allow-listed iframes.
- Uploaded images are validated (signature, type, size and dimensions) but not re-encoded or resized. That would need `sharp` as a dependency.
- Rate limits for tracking and subscribing are held in memory. That suits a single process, and the limits reset on restart. Login lockout is stored in the database.
- The link-health check runs only on demand, not on a schedule.
- Drag-and-drop uses the HTML5 API, which has no touch support. Touch and keyboard users reorder with the arrow buttons instead.
